# aihot 完整工作流与模块实现说明

> 本文档用**文字**讲清两件事：① 系统一天里到底做了什么；② 每个模块的功能是怎么实现的（讲思路、算法与取舍，**不含代码**）。
> 想快速上手看 [README.md](../README.md)；想了解设计背景与容灾取舍看 [DESIGN.md](../DESIGN.md)；项目复盘看 [PROJECT-REVIEW.md](PROJECT-REVIEW.md)。

## 0. 一分钟概览

aihot 是一个**无人值守的中文 AI 日报机器人**：每天 17:00 由 Windows 任务计划唤起，
从 16 个信息源（14 个启用）抓取最近 24 小时的内容，经过"预筛 → 事件聚类 → 大模型加工 → 排序"，
组装成一份开发者向的日报（一张长图 + 可点击文字），推送到企业微信与邮箱，并把全部产物存档到本地数据库。

三个最关键的工程特征：

1. **两层解耦**：采集与加工解耦、呈现与推送解耦 —— 所以"补发"不需要重跑大模型、结果与当天完全一致；
2. **一切失败都有降级路径**，且失败必须"看得见"（告警双通道 + 本地兜底 + 运行记录留痕）；
3. **内容范围可配置**：只收录开发者关心的内容（模型突破 / 开源工具 / 工程实践 / 研究进展）。

## 1. 一天的工作流（时间线）

| 时间 | 发生什么 | 失败会怎样 |
|---|---|---|
| 17:00 | Windows 任务计划唤起 `run_daily.bat`（唤醒计算机、仅登录时运行、错过会补跑） | 若电脑关机则等开机后补跑 |
| +3 秒 | **快速预检**：验证配置、代理、企业微信、大模型接口 | 致命项（企微/大模型）失败 → 记录"跳过+原因"并告警；代理失败 → 只降级 |
| +5 秒 | **采集**：并发抓取 14 个源，落库去重 | 单源失败被隔离；全部失败才中止并告警 |
| +1 分钟 | **加工**：预筛 → 事件聚类 → 大模型批量加工（中文标题/摘要/分类/重要度）→ 排序 | 大模型单批失败重试后按原文降级；超成本/超时间则停止后续批次 |
| +2 分钟 | **组装**：选出精选 12 条 + 论文 ≤2 篇 + 简讯 12 条 | 无新内容时跳过（不重复推送旧内容） |
| +2 分钟 | **渲染**：生成企微文字分片、邮件 HTML、长图（系统 Edge 截图） | 长图失败 → 降级纯文字并在正文标注 |
| +3 分钟 | **推送**：企业微信（图 + 文字）与邮件 | 企微失败邮件照发；两通道都失败才记未送达并告警 |
| +3 分钟 | **存档与记账**：图片/文字/HTML 落盘、日报入库、运行记录（耗时/成本/结果） | 写盘失败 → 状态置为 failed 并告警 |
| 随时 | `aihot report` 可查看 SLO 报告；`preview`/`resend` 可预览或补发历史日报 | — |

## 2. 数据流水线全景

```
        时间窗口：最近 24 小时
                 │
  ┌──────────────▼──────────────┐
  │ ① 采集（并发 14 源，单源隔离） │  RSS / HN / arXiv / HTML / GitHub×2
  └──────────────┬──────────────┘
                 │ 原始条目（标题+链接+时间+来源）
  ┌──────────────▼──────────────┐
  │ ② 预筛：垃圾 / 主题 / 相关性 / 去重 │  规则层，确定且免费
  └──────────────┬──────────────┘
                 │ 保留条目
  ┌──────────────▼──────────────┐
  │ ③ 事件聚类（同一事件合并）      │  规则为主，大模型精修可选且默认关
  └──────────────┬──────────────┘
                 │ 事件簇
  ┌──────────────▼──────────────┐
  │ ④ 大模型加工（唯一调用 LLM 的地方）│  中文标题/摘要/分类/重要度
  └──────────────┬──────────────┘
                 │ 已加工条目（写回数据库）
  ┌──────────────▼──────────────┐
  │ ⑤ 排序（重要性+跨源+热度+权重）  │
  └──────────────┬──────────────┘
                 │ 排序结果
  ┌──────────────▼──────────────┐
  │ ⑥ 组装日报（精选/论文/简讯）     │  含内容范围排除与 GitHub 条目限流
  └──────────────┬──────────────┘
                 │ 日报对象
  ┌──────────────▼──────────────┐
  │ ⑦ 渲染（文字分片 / 邮件 / 长图）  │  先存档，后推送
  └──────────────┬──────────────┘
                 │ 图片 + 文本 + HTML
  ┌──────────────▼──────────────┐
  │ ⑧ 推送（企微 + 邮件，各自降级）   │
  └─────────────────────────────┘
```

**两个重要约定**：

- **日报以数据库为准**：组装时读取的是"最近 24 小时已加工条目"这一窗口，而不是"本轮刚抓到的内容"。
  因此自动运行、预览、补发三者看到的是同一份数据，结果一致。
- **先存档、后推送**：所有产物先落盘入库，再推送。即使推送全挂，内容也不会丢，随时可补发。

## 3. 模块逐个说明（按六层）

> 每层只依赖下层，下层不感知上层 —— 这保证了"每层可单独测试、单独替换"。

### 3.1 基础层（C：配置 / 数据 / 网络 / 日志 / 诊断）

| 模块 | 职责 | 实现思路 |
|---|---|---|
| **config** | 加载并严格校验配置文件 | 先解析 YAML，再把所有问题**一次性收集**成清单（而不是遇到第一个就退出），逐项给出可操作的错误说明；密钥支持"直接写在配置里"或"指向环境变量"两种来源；提供密钥清单用于日志脱敏；把"每个信息源的权重"整理成查询表；路径统一解析为绝对路径 |
| **models** | 定义层与层之间流动的数据契约 | 用不可变风格的数据结构描述：原始条目、加工后的条目、事件簇、日报、运行记录；每条条目携带"来源 + 链接的规范化哈希"用于去重；附带语言检测与 URL 哈希工具 |
| **store** | 唯一的持久化层（SQLite） | 四张表：条目表（唯一键=来源+链接哈希，天然幂等）、事件簇表、日报表（按日期唯一，可完整重建）、运行记录表；读操作包括"待加工队列""最近窗口已加工条目""运行汇总"；写操作全部在事务里；开启 WAL 提升并发读写稳定性 |
| **net** | 统一 HTTP 客户端 | 统一浏览器 UA、超时、重试（指数退避；遇 429 优先遵循服务端给的等待时间）；**不抛异常**，失败以"结果对象"返回，由调用方决定是重试、降级还是隔离；代理只认配置（显式关闭对环境变量代理的信任），并提供**功能性健康检查**判断"代理是否真的能出网" |
| **utils** | 通用工具 | URL 规范化（去掉跟踪参数、统一大小写与末尾斜杠）、HTML 清洗、时间解析与本地日期换算、文本脱敏、语言检测 |
| **logging_setup** | 日志 | JSON 行格式落盘（便于机器分析）+ 控制台可读格式；**所有日志在写出前经过密钥脱敏过滤器**，保证密钥不会因为报错回显而泄漏 |
| **checks** | 诊断与预检 | 把探测项分成两类：**致命项**（大模型、企业微信 —— 失败就不该运行）与**可降级项**（代理 —— 失败自动改直连）；另外提供全量网络探测（逐个源的可达性）供排障使用 |

### 3.2 采集层（S：把世界变成"原始条目"）

| 模块 | 职责 | 实现思路 |
|---|---|---|
| **base** | 适配器接口与公共逻辑 | 约束"适配器只产出原始条目，不写库、不推送、不调大模型"；统一处理相对链接补全、非法链接丢弃、标题清洗、发布时间兜底（没有时间就用"发现时间"） |
| **registry** | 注册表与并发调度 | 维护"源类型 → 适配器实现"的映射；按配置构建启用的适配器；用线程池并发抓取（默认 5 个并发）；**每个源包在独立的错误边界里**，失败只记录统计与原因，绝不影响其他源 |
| **rss** | 通用 RSS/Atom | 覆盖大部分媒体源；用浏览器 UA 规避反爬；解析条目时间、摘要与链接 |
| **hackernews** | 社区热度源 | 调官方检索接口取最近窗口内的帖子；把"点数/评论数"写进条目的热度字段，供后续排序使用 |
| **arxiv** | 论文源 | 按 AI 相关分类查询最新论文；标记为"论文"类型，在日报里单独成节（每天最多 2 篇） |
| **html** | 通用网页列表适配器 | **配置驱动**：在配置里写列表项/链接/标题/时间的选择器与链接过滤规则，新站点零代码接入；选择器全部不匹配时报错（说明站点可能改版），交给单源隔离处理 |
| **github** | 开源项目源（增长榜） | 用官方检索接口取"最近 7 天新建且 star 超过阈值"的项目并按 star 降序；拿到语言/star/fork/主题等结构化字段；发布时间统一用"发现时间"，这样它才能进入当日窗口 |
| **github_trending** | 开源项目源（当日热榜） | 解析官方热榜页面：仓库名、语言、总 star、今日新增 star、fork、描述；对"不是仓库的两段路径"做前缀排除；"取前 N 条"以**解析成功**的条数为准；页面偶发 403/超时属预期，由重试与单源隔离兜底 |
| **hf_papers** | 论文源（已停用） | 本机 IP 持续被限流，果断停用并在配置里记录原因与日期 |

### 3.3 加工层（P：把条目变成"可读的日报素材"）

| 模块 | 职责 | 实现思路 |
|---|---|---|
| **prefilter** | 预筛（规则层，免费且确定） | 四道规则依次执行：**垃圾黑名单**（招聘/课程/促销/活动）、**主题排除**（硬件资讯与公司间商业消息，内置高精度词 + 可配置追加）、**AI 相关性门槛**（只对通用科技源要求命中 AI 关键词，AI 专属源直接放行）、**批内去重**；每次剔除都计数并留样本，便于事后调优 |
| **dedup** | 事件聚类（判重） | 先做"链接完全相同"的精确合并；再做**标题相似度聚类**：相似度超过阈值（默认 88）且发布时间跨度不超过 72 小时才允许并簇；用并查集把传递相似的条目合成一个事件簇；**版本号护栏**避免把同一产品的不同代次/型号误并；大模型精修可选，**默认关闭**，且开启后其结果必须通过规则校验才生效（规则有最终否决权） |
| **enrich** | 大模型加工（全项目唯一调用大模型的地方） | 批量送加工（默认按批），要求模型返回严格结构（中文标题/摘要/分类/重要度/是否 AI 相关）；对返回值做**结构校验 + 值域收敛**（分类必须在允许集合内、重要度裁剪到 0~100、非法值走兜底）；单批失败重试，仍失败则该批条目**按原文降级**（内容不丢）；已加工条目不再进入队列（不重复花钱）；全程有**每日成本上限**与**时间预算**两个护栏 |
| **prompts** | 提示词模板 | 与代码分离便于调优；分类体系固定为 8 类（模型发布/产品更新/研究突破/开源工具/融资商业/政策监管/行业动态/其他）；**内容政策写在这里**：只收录开发者向内容，硬件与商业消息归入对应分类并给低重要度；综述要求"纯文本、150~250 字、只写技术向内容" |
| **rank** | 综合排序 | 加权求和：重要性（0.55）+ 跨源提及（0.20，被越多来源报道越高）+ 社区热度（0.15，把点数/评论/star 做对数归一）+ 来源权重（0.10）+ **兴趣加成**（按分类可正可负：技术类加分、商业类负分）；同分时更新的优先 |

### 3.4 呈现层（R：把素材变成"能看的东西"）

| 模块 | 职责 | 实现思路 |
|---|---|---|
| **compose** | 组装日报 | 从排序结果里挑内容：**论文单列**（最多 2 篇）、**精选区**取前 N 条（默认 12，其中 GitHub 项目最多 4 条，避免项目挤掉新闻）、**简讯区**再取 12 条；同时执行**内容范围排除**（行业动态/融资商业/政策监管不进任何区块）与噪音排除（"其他"分类且重要度过低）；生成页脚统计 |
| **render_text** | 文字版 | 企微 markdown 按**字节预算分片**（平台限制 4096 字节，分片时保证链接不丢）；邮件用 HTML 模板（可选把长图以内嵌图片方式附上）；同时产出存档用 markdown |
| **render_image** | 长图 | 用模板把日报渲染成 HTML，再用 Playwright **驱动系统自带的 Edge**（无头模式）整页截图，零额外浏览器下载；图片导出为 JPEG，若超过平台 2MB 限制则**逐级降低质量**，仍超限则**按高度自动拆图**；视觉风格为浅色极简，序号 Top3 红、其余蓝 |

### 3.5 推送层（D：把日报送出去）

| 模块 | 职责 | 实现思路 |
|---|---|---|
| **wecom** | 企业微信群机器人 | 图片以 base64 + 校验值提交；文字按分片逐条发送；**校验返回码**（平台对失效的机器人也返回 HTTP 200，必须看业务错误码才能发现 key 失效）；**强制直连**且不信任环境变量代理 —— 这是 M5 事故后确立的原则 |
| **email** | 邮件 | 支持 SSL/STARTTLS；HTML 正文；可选内嵌长图；收件人支持多个 |
| **base** | 推送公共约定 | 统一异常类型；推送层只负责"发"，是否降级由编排层决定（例如企微失败后邮件照发） |

### 3.6 编排与运维层（O）

| 模块 | 职责 | 实现思路 |
|---|---|---|
| **runner** | 编排 | 把每个阶段做成可单独调用的函数（采集/加工/组装/渲染/推送），**手工调试与自动运行走完全相同的代码路径**；串起完整流程并做三件事：① 失败兜底告警；② 写运行记录（阶段/结果/耗时/成本/错误摘要）；③ 降级提示（如代理降级时主动通知） |
| **cli** | 命令行入口 | 提供：预检、采集、加工、完整运行、预览、补发、SLO 报告、告警、跳过记录、版本等命令；约定退出码（0 成功 / 1 运行错误 / 2 用法错误 / 3 配置错误）；统一把输出固定为 UTF-8，避免中文乱码 |
| **run_daily.bat + 任务计划** | 无人值守入口 | 触发时间 17:00、仅用户登录时运行（代理软件依附用户会话）、唤醒计算机、错过补跑、执行限时 30 分钟、同一时段不重复启动；脚本先做快速预检，通过才进入正式运行；预检失败则记录"跳过"并告警 |
| **reporting** | SLO 报告 | 汇总运行记录与存档，输出送达率、准点率、幂等（重复推送）、端到端耗时、日均成本、存档完整性；**能区分"跳过（含原因）"与"完全没运行"**（M5 事故的可观测性修复）；支持 JSON 输出供脚本消费 |
| **scripts** | 运维脚本 | 任务计划注册/注销、**发布闸门**（提交前扫描真实密钥与个人邮箱）、版本化的 git 钩子（让闸门自动生效） |

## 4. 横切机制（跨模块的"规矩"）

### 4.1 幂等（重复运行不重复花钱、不重复打扰）

- 条目唯一键 = 来源 + 链接哈希 → 同一内容重复抓取不会重复入库；
- 已加工条目不再进入加工队列 → 同一天重复运行不会二次调用大模型；
- 当天没有新内容时**不生成日报**（避免把旧内容再推一遍）。

### 4.2 降级矩阵（任何一环挂掉都有兜底）

| 环节 | 失败场景 | 降级动作 |
|---|---|---|
| 预检 | 大模型 / 企微不可用 | 记录"跳过+原因"，不发半成品，并告警 |
| 预检 | 代理不可用或节点异常 | **自动改直连**继续运行（只影响墙外源）+ 一条降级提示 |
| 采集 | 部分源失败 | 其余照常；全部失败才中止 |
| 加工 | 大模型单批失败 | 重试 → 按原文降级（内容不丢） |
| 加工 | 超成本 / 超时间预算 | 停止后续批次，已处理部分照常出报 |
| 呈现 | 长图失败 | 发纯文字版，正文开头标注 |
| 推送 | 企微失败 | 邮件照常；两通道都失败才记未送达并告警 |
| 告警 | 企微失败 | 邮件并送；两者都失败写本地告警文件 |

### 4.3 内容范围（开发者向，三道过滤 + 一层加权）

1. **规则预筛**：高精度词直接剔除（晶圆/液冷/数据中心/收购/融资/财报/人事…）；裸词（显卡/GPU/芯片/型号名）**故意不进黑名单**，避免误杀工程内容；
2. **大模型语义**：提示词要求把硬件/商业消息归入对应分类并给低重要度；
3. **组装排除**：行业动态 / 融资商业 / 政策监管三个分类不进日报任何区块；
4. **排序加权**：技术类加分、商业类负分，保证即使漏网也沉底。

### 4.4 成本与速度控制

- 批量加工 + 每日成本上限 + 时间预算三重护栏；
- 已加工缓存避免重复付费；
- 实测：端到端 1~3 分钟，成本约 ¥0.04~0.16/天（预算 ¥1/天）。

### 4.5 可观测性与安全

- **运行记录表**：每次运行都留下阶段、结果、耗时、成本、错误摘要；跳过也留痕；
- **SLO 报告**：把"感觉还行"变成数据；
- **预检分级**：可降级项不阻断运行，致命项必须告警；
- **密钥安全**：密钥只存在本地配置（不进版本库）、日志全链路脱敏、发布闸门 + git 钩子防误提交、提交者用匿名邮箱。

## 6. 常见运维动作

| 想做什么 | 怎么做（命令名） |
|---|---|
| 体检（几秒钟） | `aihot check --quick`；要逐源探测用 `aihot check --net` |
| 手工跑一次完整流程 | `aihot run`；只想看产物不推送用 `aihot run --dry-run` |
| 补发某天 | `aihot resend --date 年-月-日`（不重跑大模型，结果与当天一致） |
| 看某天长什么样 | `aihot preview --date 年-月-日` |
| 看稳定性 | `aihot report --days 14`（可加 `--json`） |
| 验证告警通道 | `aihot alert --message "测试"` |
| 记录一次跳过 | `aihot skip --reason "原因"`（预检失败时由脚本自动调用） |
| 发布到 GitHub | 提交前跑 `scripts/publish_gate.py`（已用 git 钩子自动化） |

## 7. 已知边界（诚实声明）

- 单机运行：电脑长期关机那天不会有日报（靠"错过后补跑"缓解，无分布式与备份）；
- 大模型供应商单一（DeepSeek）：故障时降级为原文推送，换供应商只需改加工层一个模块；
- 部分源依赖代理：代理不可用时这些源会缺（其余源照常），系统会自动降级并提示；
- GitHub"增长最快"是近似口径：一个是"近 7 天新建 + star 最多"，一个是"当日热榜"，两者互补但都不是精确的增量榜；
- 个人微信接收：企业微信外部群不支持机器人（官方限制），需通过"微信插件 + QQ 邮箱提醒"绕行。
