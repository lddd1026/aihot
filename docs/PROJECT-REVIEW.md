## 一、个人贡献

**一句话**：独立完成了一个"从需求定义到生产运行"的完整系统——包括架构设计、信息源接入、
LLM 加工链路、长图渲染、双通道推送、无人值守运维，以及一套**让 AI 产物可被信任的验证机制**。

| 维度 | 具体贡献 |
|---|---|
| **需求定义** | 把"每天看 AI 热点"翻译成可验收规格：Top 10~15、17:30 前送达、长图+文字、企微+邮件、成本 ≤¥1/天、明确排除微博/知乎 |
| **产品决策** | 浅色极简长图 · 序号 Top3 红/其余蓝 · 邮件只发文字版 · 日报以"数据库窗口"为准（预览/补发/自动运行三者一致） |
| **工程实现** | 6 层架构（采集/加工/呈现/推送/存储/运维）· 约 6.7k 行源码 / 36 文件 · 15 个源接入（14 启用）· 380+ 单元测试 |
| **质量机制（最独特）** | 「开发与验收分离」门禁：每个里程碑由**冷启动的独立测试 Agent** 黑盒验收，P0/P1 清零才推进；累计 100+ 独立脚本 / 22k 行 |
| **运维与事故处理** | 首个 14 天观察期只送达 4/14 → 定位根因（代理单点依赖导致静默失败）→ 修复 8 项 → 独立复验 75 项断言全绿，观察期重新计时 |
| **交付** | 门禁/复盘报告 10+ 份、全量证据留档，已开源发布（含密钥脱敏与提交前扫描闸门） |

> 工作方式：需求与验收标准由人定义、产品判断由人做出、"什么时候算通过"由人决定；
> 实现由 AI 编程助手完成；**验收由另一个独立 AI Agent 冷启动执行**（禁止改源码、禁止真实推送、只连本地假服务）。
> 这套"人定标准 → AI 实现 → 独立 AI 验收"的流程，是项目里最值钱的方法论。

## 二、核心问题

表面是"抓新闻"，实际要解决 5 个真问题：

1. **信息不是太少而是太碎**：15 个中英文源（媒体/社区/官方/论文/开源项目），同一事件被多家重复报道
   → 需要**判重 + 事件聚类**，而不是简单罗列
2. **"重要性"无法用规则直接定义**：要结合来源权重、多源提及数、社区热度（HN 分数、GitHub star 增速）、时间新鲜度
   → 分层信号融合
3. **英文内容要变成中文可读**：不是机翻，而是"中文标题 + 一句话摘要 + 分类 + 重要度"的结构化加工
4. **要在手机上 3 分钟看完**：长图 + 可点击文字，且企微图片有 2MB 硬限制
5. **无人值守下"失败必须可见"**：本轮最大教训——**静默失败比失败本身危险得多**

## 三、方案设计

**分层架构（依赖单向，下层不感知上层）**

```
O 编排层  CLI / runner / Windows 任务计划
   │
C 采集 ── S 加工 ── P 呈现 ── R 推送
   │        │         │        │
   └── D 存储(SQLite) + 运维(日志/预检/SLO 报告)
```

**关键设计决策**

| 决策 | 目的 |
|---|---|
| 采集与加工解耦、呈现与推送解耦 | `resend` 补发不重跑 LLM（省钱、结果可复现） |
| LLM 只出现在 enrich 一层 | 其余全是确定性代码，可测试、可回溯 |
| 日报以"数据库最近 24h 窗口"为准 | 预览/补发/自动运行三者结果**永远一致** |
| 规则聚类为主 + LLM 精修默认关闭 | 规则有最终否决权（LLM 曾把 10 条不相关新闻并成 1 条） |
| 单源失败隔离 | 15 个源里挂几个是常态，日报照常出 |
| 一切失败都有降级路径 | 见下表 |

**分层降级矩阵（容灾设计的核心）**

| 环节 | 失败 | 降级动作 |
|---|---|---|
| 预检 | 代理（Clash）不可用 | **降级直连**继续跑（只影响墙外源）+ 通知 |
| 预检 | LLM / 企微不可用 | 记录"跳过+原因"到数据库，不发半成品 |
| 采集 | 部分源失败 | 其余照常；全部失败才中止 |
| 加工 | LLM 单批失败 | 重试 → 按原文降级（**内容不丢**） |
| 加工 | 超成本/时间上限 | 停止后续批次，已处理部分照常出报 |
| 呈现 | 长图渲染失败 | 发纯文字版（开头标注 ⚠️） |
| 推送 | 企微失败 | 邮件照常发；两通道都失败才记未送达并告警 |
| 告警 | 企微失败 | 邮件并送；都失败写本地 `logs/ALERTS.log` |

## 四、技术取舍

| 取舍 | 选择 | 理由 |
|---|---|---|
| **LLM 用不用在聚类上** | 默认不用，只留开关 | 实测 LLM 会把不相关新闻合并；规则准确率 99.79%，成本为零、结果确定 |
| **GitHub 怎么取数** | **双源互补**：Search API（近 7 天新建 + star 最多）+ Trending 页（当日热榜） | 前者对应"增长最快的新项目"，后者对应"今天正在火的项目"；互为补充且单源隔离 |
| **Trending 页风险** | 网页解析 + 重试 + 单源隔离 | 页面偶发 403/429/超时属预期；失败只影响这一个源 |
| **Reddit 怎么抓** | 官方 RSS + 浏览器 UA | JSON 接口 429 严重 |
| **长图渲染引擎** | Playwright 驱动**系统 Edge** | 不下载 Chromium 内核（省 ~150MB 依赖与安装失败风险） |
| **长图超 2MB 怎么办** | JPEG 质量阶梯降级 → 仍超则**自动拆图** | 企微硬限制，拆图保证不丢内容 |
| **推送格式** | 企微（图+文字）、邮件（纯文字） | 明确要求；邮件内嵌图保留为配置开关 |
| **数据源取舍** | HF Papers（持续 429）、机器之心（改版落地页）→ **停用** | 宁可少一个源，不要每天报错；停用原因写进文档 |
| **内容范围取舍** | 只收录开发者向内容（模型/开源工具/工程/研究）；硬件与商业消息不收 | 用"规则宁漏勿错 + LLM 语义判定 + 组装层兜底"三层实现，避免规则层误杀工程贴 |
| **任务计划执行条件** | "仅用户登录时运行" | 代理软件依附用户会话，服务模式下不可用 |
| **失败即停 vs 降级运行** | **最终改为降级运行** | 第一轮观察期血的教训：失败即停 = 10 天静默 |
| **告警通道** | 企微 + 邮件**双通道并送** + 本地文件兜底 | 单通道会随代理/服务一起挂；"告警本身挂了"是最危险的失败模式 |
| **成本控制** | 批量加工 + 每日成本上限 + 时间预算 | 实测 ¥0.04~0.16/天，预算 ¥1 |

## 五、验证方式

**四层验证，从便宜到贵：**

| 层级 | 做法 | 规模 |
|---|---|---|
| ① 单元测试 | 纯离线、mock 网络与 LLM | **380+ 用例** |
| ② 独立门禁（核心） | **冷启动测试 Agent**：只看验收标准、禁止改源码、禁止真实推送（本地假企微/假 SMTP/假 LLM/假 RSS）、必须尝试证伪 | **100+ 脚本 / 22k 行**，产出 M0–M4 门禁报告 + M5 修复验收报告 |
| ③ 真机验证 | 真实抓取、真实推送、真机看长图、真跑任务计划 | 每轮改动后 `resend` 到手机确认 |
| ④ 观察期 + SLO | 14 天无人值守运行，`aihot report` 对照验收标准（送达率/准点率/幂等/成本/存档） | 第 1 轮 4/14 ❌ → 修复 → 第 2 轮进行中 |

**门禁真的抓到过东西**（P0/P1 全部在推进前清零）：
- P0：配置报错时**回显含密钥的 YAML 原文**
- P1：企微坏 key 检测不出（qyapi 对坏 key 也返回 HTTP 200，必须解析 `errcode`）
- P1：长图渲染失败**不告警**且 `runs` 记成成功
- P1：LLM 过度合并、簇编号覆盖历史
- P1（修复轮）：**环境变量代理能绕过"直连"** —— 复验时抓出，二次修复并复验通过

## 六、实际结果

**✅ 达标的**

| 指标 | 结果 | 目标 |
|---|---|---|
| 成本 | **¥0.04~0.16/天** | ≤ ¥1 |
| 速度 | 端到端 **89~103 秒** | < 25 分钟 |
| 幂等 | **0 重复推送** | 0 |
| 内容 | 1,100+ 条目 / 800+ 事件簇 / 多期存档 | 不丢内容 |
| 质量 | `ruff` 零告警 · 单测全绿 · 独立验收全绿 | — |
| 稳定性（工程侧） | 15 源单源隔离 · 三层降级 · 关键路径全部有自动化回归 | — |

**⚠️ 真实事故（也是最有价值的部分）**

第 1 轮 14 天观察期：**只送达 4 天**。根因链：

```
10 天没收到日报 → 预检把"代理不可用"当致命错误整日跳过
→ 企微/LLM/预检/告警全被强制走代理（都是国内服务！）
→ 告警自己也发不出 + 跳过不写数据库 = 静默失败
```

修复 8 项后：`check --quick` 在 Clash 关闭时退出码 0、**13 源 12 源直连成功**；
独立复验 8 套 75 项断言全绿、P0/P1 清零；第 2 轮观察期 2026-10-12 重新计时（至 10-25）。

**已交付**：开源在 `github.com/lddd1026/aihot`（密钥脱敏 + 提交前扫描闸门验证过）。

## 七、已知边界（诚实声明）

- 单机运行：电脑长期关机那天不会有日报（靠"错过后补跑"缓解，无分布式）
- 无备份：硬盘坏了会丢历史（存档都在本地）
- LLM 供应商单一（DeepSeek）：故障时降级为原文推送，换供应商只需改 enrich 一层
- GitHub"增长最快"：Search API 是近似（近 7 天新建 + star 最多），Trending 页是当日榜
- 代理状态：已加**功能性健康检查**（端口通 ≠ 节点可用），"Clash 端口开着但节点坏"时自动降级直连；
  健康检查自身依赖 gstatic 可达性，极端情况下可能误判为降级（仅影响源数量，不影响出报）
- 个人微信接收：企业微信外部群不支持机器人（官方限制），已给出"微信插件 + QQ 邮箱提醒"绕行方案
