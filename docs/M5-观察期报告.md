## 二、根因分析（5 Whys）

| 层 | 问题 | 答案 |
|---|---|---|
| 1 | 为什么 10 天没收到日报？ | 每日运行在预检阶段被整日跳过 |
| 2 | 为什么会被跳过？ | 预检把"代理探测失败"当成致命错误 |
| 3 | 为什么代理没开就整体失败？ | **企微 webhook / LLM / 预检 / 告警 全部被强制走代理**——这三项本身都是国内直连服务 |
| 4 | 为什么没有任何提示？ | 告警自己也走代理（发不出），且跳过的运行**不写入 `runs` 表**，SLO 报告只能看到"缺 10 天" |
| 5 | **根本原因** | ① 通道未分流（直连 vs 代理）② 预检未分级（致命 vs 可降级）③ 失败不可观测（跳过无记录） |

> 幸运的是：内容与成本指标全程达标（4 次成功运行 0 重复推送、平均 89 秒、日均 ¥0.04），
> 说明问题**只出在可用性设计**，不是数据链路质量。

## 三、修复内容（已合入，含单元测试）

| # | 修复 | 位置 |
|---|---|---|
| 1 | 企微 / LLM / 邮件 / 告警**强制直连**（国内服务不依赖代理） | `delivery/wecom.py`、`checks.py`、`runner.py`、`cli.py` |
| 2 | 代理探测改为**可降级项**：不可用时自动降级直连（短超时），不再拦截运行 | `net.py`（`resolve_proxy`）、`runner.fetch_stage`、`cli._cmd_check` |
| 3 | 告警双通道并送：企微(直连) + 邮件(直连)；两者都失败则写本地 `logs/ALERTS.log` | `runner.send_alert` |
| 4 | 新增 `aihot skip --reason`：跳过写入 `runs` 表（`status=skipped`+原因） | `cli._cmd_skip`、`runner.record_skip`、`run_daily.bat` |
| 5 | SLO 报告区分"跳过（有原因）"与"没运行" | `reporting.py`（`skipped_days`） |
| 6 | 降级运行时推送一条「运行降级提示」（知情权优先） | `runner.run_all` |
| 7 | **复验补充**：直连客户端一律 `trust_env=False`（忽略 `HTTP(S)_PROXY`/`ALL_PROXY` 环境变量代理，防同类隐患） | `net.py`、`delivery/wecom.py`、`checks.py` |
| 8 | **复验补充**：`aihot alert` 兜底写文件时打印明确提示（不再"rc=1 但零输出"） | `cli._cmd_alert` |
